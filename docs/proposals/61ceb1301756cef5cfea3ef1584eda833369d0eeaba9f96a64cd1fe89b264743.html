04 / 08 · 기존 #19의 등록 목표·일감은 변경하지 않았습니다. 시간 배분은 PD의 제안 예시입니다.

측정 출처 · Pulse

같은 정의, 같은 7일로 비교합니다.

  1. 접근과 정의 확인 — 기존 Pulse의 WSLPad 일별 DAU, 사용자 식별·집계 기준, KST 일 경계를 확인합니다.
  2. 7개 완료일 기록 — 기존 자료에서 일별 DAU와 관측 기간을 읽습니다. 첫 유효 7일 평균을 비교 기준값으로 남깁니다.
  3. 평균과 격차 보고 — 7일 평균 DAU = 일별 DAU 합 ÷ 7. 목표 대비 격차 = 실측 평균 − 해당 목표값입니다.
  4. 작은 개선 판단 — 배포 내역과 사용 추이를 함께 보고, 기존 승인 범위에서 다음 묶음을 선택합니다.

미측정은 unknown입니다. 빠진 날을 0으로 채우거나 머지 수로 대체하지 않습니다. 7개 일별 값이 완전하지 않거나 집계 정의가 확인되지 않으면 평균·격차도 unknown으로 보고합니다.

기존 Pulse 접근이나 집계 자료가 없으면 측정 차단 상태를 기록합니다. 이 제안은 새 추적 코드·개인정보 수집 방식·유료 통계 서비스 도입을 포함하지 않습니다. 추가 비용이나 큰 방향 변경은 별도 PLC 변경 제안으로 올립니다.

효과 · 비용 · 위험

작은 목표로 판단 기준을 만들고, 불확실성은 드러냅니다.

기대 효과

  • 기능 수정과 실제 사용 추이를 같은 보고에서 확인합니다.
  • 7일 배포 창으로 작업을 작게 묶고 미검증 작업의 완료 표시를 막습니다.
  • 기존 Explorer·Console와 안정성 작업을 고르는 기준이 생깁니다.

비용

추가 지출 요구 없음. 기존 PC·구독·Pulse 접근만 사용합니다. 실제 구독 사용량·처리 시간·기회비용은 unknown입니다.

위험과 대응

  • 기준값 부재: 1·3·5 목표가 낮거나 높을 수 있습니다. 첫 실측 후 새 정보로 목표 재검토를 요청합니다.
  • 자원 대기: 창 안에 검증이 끝나지 않을 수 있습니다. PD가 다음 7일 이하 창으로 조정하며 성공으로 꾸미지 않습니다.
  • 사용 추이 해석: DAU 변화만으로 특정 수정의 효과를 단정하지 않습니다.
  • 릴리스 QA: #107의 집 PC Hyper-V 격리 조건과 기존 수동 릴리스 절차를 유지합니다.

기존 7일 운영 안에서
DAU 목표 1·3·5명을 채택할까요?

A. 유지형 1·3·5명 — 추천

단기 / 분기 / 연간 7일 평균 DAU 목표를 1 / 3 / 5명으로 정합니다. 낮은 우선순위를 유지하며 작은 절대 목표와 실측부터 운영합니다.

B. 성장형 1·5·10명

같은 기간과 Pulse 측정법으로 1 / 5 / 10명을 추구합니다. 목표 부담과 미달 가능성이 더 큽니다. 추가 비용·전담 자원 배정을 뜻하지 않습니다.

C. 자유 입력

원하는 단기·분기·연간 수치와 기간을 직접 적어주세요. PD가 기존 합의와 영향·비용을 확인해 반영안을 정리합니다.

추천 이유: 현재 사용 규모가 unknown이므로 낮은 우선순위에 맞는 작은 목표부터 시작하는 편이 적절합니다. 승인 후 PD가 합의 원문·출처와 목표를 정리하고 코어의 기존 게시 경로로 반영합니다.

권장 답변 기한: 2026-11-18 18:00 KST — 다음 배포 창 전. 늦어지면 새 목표는 미합의 상태를 유지하고 기존 버그·유지보수는 계속합니다. 게시 후 이 제안은 의종 결정 대기입니다.
