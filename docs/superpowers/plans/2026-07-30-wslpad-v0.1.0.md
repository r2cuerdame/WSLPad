# WSLPad 0.1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Spec:** `goal.md` (repo root) is the authoritative specification. Every task below cites the goal.md sections it implements. Where this plan and goal.md conflict, goal.md wins.

**Goal:** Ship WSLPad 0.1.0 — a Windows-only Electron tray app with WSL Dashboard, Explorer, bottom Console, and a read-only local MCP server, packaged as an NSIS installer with GitHub-Releases auto-update, released as `v0.1.0` on github.com/r2cuerdame/WSLPad.

**Architecture:** Electron (main/preload/renderer) built with electron-vite. Main process owns all WSL access through a Hidden Runner (`wsl.exe` child processes, agentless), a polling state store producing a single JSON-serializable `WslPadSnapshot`, a node-pty ConPTY interactive console per distro, explorer file operations, settings persistence, tray lifecycle, electron-updater, and an MCP Streamable-HTTP server bound to 127.0.0.1. Renderer is React + i18next with exactly two main tabs (Dashboard, Explorer) plus an always-present bottom Console (xterm.js) and a settings drawer. All IPC is typed, allowlisted, and goes through a contextIsolation preload bridge.

**Tech Stack (pinned):** electron ^33, electron-vite ^3 + vite ^6, TypeScript ^5.7, React 18.3, @xterm/xterm ^5.5 (+fit addon), node-pty ^1.0 (rebuilt via electron-builder install-app-deps; fallback `@homebridge/node-pty-prebuilt-multiarch`), electron-builder ^25 (NSIS), electron-updater ^6, @modelcontextprotocol/sdk ^1, zod ^3, i18next ^24 + react-i18next ^15, vitest ^2, @playwright/test ^1 (Electron E2E), eslint ^9 flat + typescript-eslint.

## Global Constraints (from goal.md — verbatim rules)

- Windows-only. Node >= 20 floor (dev machine: Node 24.13.1).
- Exactly 2 main tabs: Dashboard, Explorer. No third main tab ever (settings = drawer/modal).
- Dashboard is read-only; state-changing actions only *prepare* commands into the Console input (never execute).
- Console executes only what the user submits with Enter. No auto-execution, no auto-sudo.
- MCP is read-only: every tool named `Get*`; no Run/Write/Delete/Set/Kill/Install/Restart tools. 127.0.0.1 bind only, Origin validation, local Bearer token.
- Hidden Runner commands and internal `cd` sync NEVER appear in user Console transcript or shell history.
- Secret masking (names containing KEY, TOKEN, SECRET, PASSWORD, PASS, AUTH, CREDENTIAL, COOKIE, PRIVATE, SESSION, BEARER) in UI-by-default and ALWAYS in MCP responses. Private-key file contents never returned by MCP.
- 9 locales exactly: ko, en, ja, zh-CN, zh-TW, es, fr, de, pt-BR. Key parity enforced by test. No hardcoded user-facing strings.
- Renderer: contextIsolation on, nodeIntegration off, typed preload IPC, explicit channel allowlist, command escaping, distro/path validation.
- Settings cannot weaken safety invariants (no auto-run, MCP read-only, localhost bind, no auto-sudo).
- Production code has no TODO placeholders; fixture data never appears in real mode (fixture provider selected only by `WSLPAD_FIXTURE_MODE=1`).
- `wsl.exe` output is UTF-16LE on this machine — all wsl.exe stdout parsing must decode UTF-16LE (strip NULs/BOM) and must not depend on localized header/state words.
- Version `0.1.0`; publish config `provider: github, owner: r2cuerdame, repo: WSLPad`.
