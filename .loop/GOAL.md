## 코드가 말하는 목표 (초안)

WSLPad는 WSL을 쓰는 Windows 사용자를 위한 **작은 상주형 동반 도구**로 보인다. 부제는 저장소 전체에서 일관되게 "A small Windows companion for WSL."이며, 거대한 IDE나 배포판 관리자를 지향하지 않는 것으로 읽힌다.

해결하려는 문제는 "WSL 안에서 벌어지는 일이 Windows 쪽에서 보이지 않는다"인 듯하다 — 어느 배포판이 실제로 응답하는지, 도구가 어디에 설치됐는지, 어떤 포트가 어디까지 닿는지, 내가 쓴 설정이 정말 적용됐는지.

## 제품 정체성 (코드가 강제하는 네 개의 면)

1. **Dashboard** — 읽기 전용 상태 조회. 좌측 섹션 목록 + 우측 상세의 master–detail, 현재 16개 섹션.
2. **Explorer** — 좌 Windows / 우 WSL 2분할. 두 패널 사이 복사가 주 상호작용.
3. **Console** — xterm.js + node-pty 실 셸. 실행 책임은 전적으로 사용자에게 있는 것으로 보인다.
4. **읽기 전용 MCP** — 127.0.0.1 로컬 HTTP, `Get*` 37개, 쓰기 경로 없음.

## 지켜지고 있는 것으로 보이는 원칙

- **선언된 것과 실제인 것을 구분한다.** 0.5.0 변경 이력의 중심 명제이고, liveness 프로브 · interop binfmt 노드 · 레지스트리 `DefaultUid` vs `[user] default=` · portproxy 규칙의 live/stale 판정 · Docker Desktop의 실제 저장 배포판이 모두 이 원칙의 구현으로 읽힌다.
- **모름은 부정이 아니다.** 타입 전반이 `number | null`, `boolean | null`이고, 수집 실패는 0이나 false가 아니라 null + 사유로 남는다. 캐시가 비었다고 보고하는 것을 가장 경계하는 형태다.
- **읽기 전용은 구조로 보장한다.** Dashboard 버튼은 명령을 Console 입력줄에 *준비*만 하고, MCP에는 변경 경로가 아예 존재하지 않으며, 비밀 값은 스냅샷에 들어가기 전에 마스킹된다.
- **내부 조회는 사용자 Console에 보이지 않는다.** Hidden Runner는 별도의 단명 `wsl.exe` 자식 프로세스이며 사용자 PTY를 건드리지 않는다.
- **실패해도 화면은 죽지 않는다.** 수집기 실패는 마지막 정상값을 유지하고 경고로만 드러난다.

## 성공 기준 (초안 — 코드·문서에서 유추)

- 설치형(NSIS, per-user, 관리자 권한 불필요) + 트레이 상주 + GitHub Releases 자동 업데이트가 동작할 것.
- WSL이 없어도 크래시하지 않고 안내 화면을 보여줄 것.
- 9개 언어(ko/en/ja/zh-CN/zh-TW/es/fr/de/pt-BR) 완전 지역화 유지.
- `WSLPAD_FIXTURE_MODE=1` 로 WSL 없이 전체 앱을 결정론적으로 구동·검증할 수 있을 것.
- MCP를 통해 쓰기 작업이 가능한 경로가 단 하나도 생기지 않을 것.

## 비목표 (goal.md §20 및 README가 명시)

배포판 마켓플레이스/삭제 관리자/clone/VHD 관리, USB forwarding, port forwarding **관리자**, Docker Desktop 대체, VS Code 대체, full IDE, Git GUI, 디버거, language server, 클라우드 동기화, 계정, 팀 협업, 원격 SSH 클라이언트, AI 채팅 UI, 앱 자체 LLM 호출, **MCP를 통한 쓰기**, 자동 문제 해결, 자동 sudo, 자동 패키지 설치, 자동 서비스 재시작.

## 대표 확정이 필요한 열린 질문

- **텍스트 에디터 방향.** 최근 지시(DIR-0001/0002)는 "WSL에서 텍스트 에디터·메모장을 쓸 때의 불편함"을 조사하라고 요구했다. 현재 코드의 편집 기능은 Explorer에 종속된 부속 편집기(2MB 상한, 원자적 저장, 문법 강조 없음)이며, 이를 **독립 제품 축으로 승격**하는 것은 위 "VS Code 대체 금지" 비목표와 경계가 맞닿는다. 확장인지 전환인지 확정이 필요하다.
- **다음 릴리스의 범위.** README 로드맵은 "VHDX 축소·확장 명령 준비, ARM64 빌드, 서명된 설치 프로그램"을 다음으로 적고 있으나 원장에는 승인된 마일스톤이 없다.
