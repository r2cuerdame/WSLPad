- 2026-08-08: **저장소를 다룰 때 반드시 알아야 할 사실** - `goal.md`(88KB)가 이 프로젝트의 실질적 명세서다. §1.3 "사양 변경 이력"이 나머지 서술보다 **우선**하며, 0.1.2부터 0.5.0까지 각 릴리스가 무엇을 왜 바꿨는지 근거(GitHub 이슈 번호, 실기계 관찰값)와 함께 적혀 있다. 코드 주석도 대부분 `goal.md §N` 을 참조한다. - 코드 전반의 서술 톤이 특이하다 — 주석이 "무엇을 하는가"가 아니라 **"왜 null 인가", "왜 0이 아닌가"**를 설명한다. 수정 시 이 규약을 깨지 말 것. - **절대 규칙 4가지**(`.github/CONTRIBUTING.md` 및 코드 구조가 강제):   1. 모든 WSL 접근은 main 프로세스에서만.   2. MCP 는 읽기 전용 — 변경 경로를 만들지 말 것.   3. 내부 조회는 사용자 Console 전사(transcript)에 나타나지 말 것.   4. 세 번째 메인 탭을 추가하지 말 것(앱의 `role="tab"` 은 정확히 2개). - 백엔드 선택은 `src/main/wsl/factory.ts` **단 한 곳**에서만 일어난다. fixture 를 추가하려면 여기를 거쳐야 하고, 그 외 경로로 fixture 를 주입하면 프로덕션 오염 위험이 생긴다. - `WSLPAD_FIXTURE_MODE=1` 로 WSL 없이 전체 앱을 결정론적으로 구동할 수 있다. E2E 전부가 이 모드다. - 선택적(`?`) provider 메서드 15개는 의도된 설계다 — 없으면 해당 섹션이 `null`(모름)이 되며, 이것이 "false(없음)"와 구분되는 것이 이 앱의 핵심 가치다. optional 을 required 로 바꾸면 그 구분이 무너진다. - `.loop/office/` 는 `.loop/.gitignore` 에 의해 git 에서 제외된다. 원장은 로컬 상태다. - 이 기계의 빌드 함정은 이미 알려져 있다(메모리 참조): flaky 다운로드 때문에 `electronDist: node_modules/electron/dist` 를 고정했고, node-pty 는 prebuild 를 쓰므로 `npmRebuild: false`, `wsl.exe` 관리 명령 출력은 UTF-16LE, rc 주입 문자열은 인용 처리에 민감하다.
